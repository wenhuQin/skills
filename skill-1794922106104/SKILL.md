# 归档文档到项目私有仓库

## 目标
把已经定稿或已归档的项目文档提交到指定 GitHub 仓库：保持正文、只改文档、仓库保持私有，并开一个仅含文档的拉取请求，未经要求不要合并。

## 步骤
1. 先核对清单与仓库。确认要提交的是哪个项目的哪些文档；只收录该项目相关材料，不要把其他项目或待分类杂文件混入。若存在名称相近的其他项目，先分清再动手。
2. 推送前用 API 重新读取目的仓库可见性，不要只依据先前任务或口头结论。用户要求私有时，若不是 private，不要推送，也不要用常见代码托管集成去改可见性（通常没有该权限，强行修改会被拒绝）。请用户在仓库设置中自行改为 Private，确认后再继续。
3. 按原文入库，不要改写、摘要或翻译正文。把完整档案树放到仓库约定的文档归档目录（以当时约定为准；若无约定可用 `docs/档案/`）；同时把现行官方文档复制到仓库惯用的文档路径，但不要覆盖无关的已有文件。
4. 只提交文档。不要改应用代码、测试、配置或 CI，也不要改仓库可见性。如需在根 README 的文档区加一行指向归档目录的指针，仅在该 README 已有文档区时才做。
5. 开一个只含文档的拉取请求，目标为默认分支。不要合并，除非用户明确要求。不要改动仓库里其他仍打开的代码拉取请求。若用户稍后只要求合并代码，不要顺带合并这份文档拉取请求。
6. 完成后回报：拉取请求地址、入库路径、仓库可见性（再次核对仍为 private），以及未改动的内容。

## 注意
- 具体仓库名、目录和可见性范围以当时用户约定为准，不要写死在本技能里。
- 文档正文保持原样，需要调整的只是放置位置和必要的索引或指针。
- 未经要求不要合并，也不要为了归档去改代码或可见性。
